# csvtidy

*[English version](README.en.md)*

Консольная утилита на Go, которая приводит в порядок «грязные» CSV-выгрузки и считает быстрые сводки. Один исполняемый файл, **только стандартная библиотека**, без зависимостей.

С выгрузками из 1С, Excel и CRM обычно одно и то же: файл в Windows-1251, разделитель `;`, даты в трёх форматах, суммы вида `1 234,50`, `2 500 руб.` и `1,234.50`, лишние пробелы и повторяющиеся строки. `csvtidy` исправляет это за один запуск и сообщает, что именно сделал и какие ячейки не смог разобрать.

## Что умеет

| Команда | Что делает |
|---|---|
| `clean` | определяет кодировку (UTF-8 или Windows-1251) и разделитель (`;` `,` табуляция `\|`); убирает лишние пробелы; числа приводит к виду `1234.5`, даты к `2024-03-05`; удаляет строки, ставшие точными дубликатами; пишет UTF-8 |
| `stats` | описывает колонки: тип (число, дата, текст), сколько заполнено и пусто, сколько разных значений, минимум и максимум, самое частое значение |
| `sum` | складывает числовую колонку по значениям другой: «выручка по менеджерам», «сумма по категориям» |

## Быстрый старт

Нужен Go 1.22 или новее.

```bash
git clone https://github.com/EminChyldyrly/csvtidy
cd csvtidy
go build -o csvtidy .

./csvtidy clean docs/example_orders.csv -o clean.csv
./csvtidy stats docs/example_orders.csv
./csvtidy sum clean.csv -by Категория -sum Сумма
```

Файл `-` означает стандартный ввод, поэтому команды собираются в конвейер: `csvtidy clean - < raw.csv | csvtidy sum - -by Менеджер -sum Сумма`.

### Пример

Исходный файл [`docs/example_orders.csv`](docs/example_orders.csv): Windows-1251, разделитель `;`, 32 строки, из них две точные копии, даты в четырёх форматах, суммы в разной записи.

```
Номер;Дата;Менеджер;Категория;Сумма;Кол-во
A-1001;15/05/2024;Петров С.; техника;15,400.00;3
A-1002;2024-04-04;Козлов Д.;Канцелярия;2 500,00;7
A-1003;15.6.24;Козлов Д.;Канцелярия;320,00;1
```

`csvtidy clean docs/example_orders.csv -o clean.csv` пишет отчёт в стандартный поток ошибок:

```
кодировка: windows-1251, разделитель: ';'
строк: 32 → 30 (дубликатов убрано: 2), исправлено ячеек: 63
  Номер                    текст
  Дата                     дата
  Менеджер                 текст
  Категория                текст
  Сумма                    число
  Кол-во                   число
проблемные ячейки (2), оставлены как есть:
  строка 8, "Сумма": "договорная" — не число
  строка 10, "Дата": "31.02.2024" — не дата
```

Результат ([`docs/example_clean.csv`](docs/example_clean.csv)):

```
Номер,Дата,Менеджер,Категория,Сумма,Кол-во
A-1001,2024-05-15,Петров С.,техника,15400,3
A-1002,2024-04-04,Козлов Д.,Канцелярия,2500,7
A-1003,2024-06-15,Козлов Д.,Канцелярия,320,1
```

`csvtidy sum docs/example_clean.csv -by Категория -sum Сумма`:

```
   Категория|  строк|     Сумма|
  Канцелярия|     10|  111790.3|
      Мебель|      7|  110019.8|
     техника|     12|     99660|
       ИТОГО|     29|  321470.1|
пропущено строк без числа в колонке "Сумма": 1
```

## Как читаются числа и даты

- **Числа:** `1234`, `1 234,50`, `1,234.50`, `1.234,50`, `2 500 ₽`, `2500 руб.`, `$15`, `-12`, `(12)` (отрицательное), `15%`. Если есть и точка, и запятая, десятичным считается последний знак. Один разделитель один раз — десятичный (`1,5` и `1.5` — это 1,5). Один и тот же разделитель несколько раз — разделитель тысяч, и группы должны быть по три цифры (`1,234,567`), поэтому `1.2.3` числом не считается.
- **Даты:** день идёт первым — `03.04.2024` это 3 апреля. Поддерживаются `05.03.2024`, `5.3.24`, `05/03/2024`, `05-03-2024`, `2024-03-05`, `2024.03.05`; время после даты отбрасывается. Несуществующие даты (`31.02.2024`) и годы вне 1900–2100 не принимаются, чтобы обычные числа не принимались за даты.
- **Тип колонки** определяется по значениям: если не менее 80 % заполненных ячеек разбираются как даты (или как числа), колонка получает этот тип. Ячейки, которые не подошли, остаются как были и попадают в отчёт о проблемах, ничего не пропадает молча.

## Коды выхода

`0` — успех; `1` — ошибка файла или данных (нет файла, пустой файл, нет такой колонки); `2` — неверное использование (нет аргумента, неизвестная команда).

## Как проверяется качество

`go test ./...` запускает 20 тестов (многие табличные, с десятками случаев), покрытие — около 97 % у пакета `tidy` и 82 % у программы целиком.

- Разбор чисел и дат проверяется на списке допустимых и недопустимых записей, включая граничные случаи: високосный день, `31.02`, год 1800, `1.2.3`, `1,2,3.4`, неразрывный пробел и юникодный минус.
- Таблица Windows-1251 проверяется по длине (128 символов) и по всему алфавиту `А–я`.
- `clean` повторно применённый к своему же результату ничего не меняет (идемпотентность).
- Команды запускаются целиком через функцию `run`: стандартный ввод, запись в файл, флаги после имени файла, коды выхода.

Я также вручную портил исходный код (меняя порог типа колонки, порядок сортировки, проверку дубликатов, формат даты, выбор десятичного знака и т. п.), чтобы убедиться, что тесты это замечают. Перебор был выборочным, это не автоматизированный прогон мутационного тестирования.

```bash
go test ./...
go test -cover ./...
```

## Структура

```
main.go          команды clean / stats / sum, разбор флагов, коды выхода
tidy/decode.go   определение кодировки и декодирование Windows-1251
tidy/parse.go    ParseNumber, ParseDate, нормализация пробелов
tidy/table.go    чтение и запись CSV, определение разделителя, заголовки
tidy/ops.go      типы колонок, Clean, Stats, GroupSum
docs/            пример «грязной» выгрузки и результат очистки
```

## Ограничения

- Кодировки только UTF-8 и Windows-1251; другие (например KOI8-R, UTF-16) не определяются.
- Файл целиком читается в память, поэтому для файлов в сотни мегабайт утилита не рассчитана.
- Написания текста не объединяются: «Техника» и «техника» остаются разными значениями (в `sum` они складываются вместе, регистр там не учитывается).
- Дата в формате с месяцем словами («5 марта 2024») не разбирается.
- Формат `.xlsx` не поддерживается, только CSV.
